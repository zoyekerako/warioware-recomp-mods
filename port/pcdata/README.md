# pcdata — ROM data as C, for the PC build only

The GBA build takes data as it sits in the ROM: beatscripts as assembled `.bs`,
everything else as raw blocks under `bin/`. Both store pointers as four bytes,
which truncates on a 64-bit host — so the same information has to be laid out by
the host compiler instead.

These files are generated, not hand-written, and they sit deliberately **outside**
the decompilation tree: its Makefile collects `data/*.c`, and a second
`scene_title` would break the ROM build.

| generated by | content |
|---|---|
| `tools/bs2c.py` | `scenes/*/scene_bs.c` — beatscripts |

`bs2c.py --verify` compiles its own output back with agbcc and compares it byte
for byte with the assembled `.bs`. Only what matches lands here.
